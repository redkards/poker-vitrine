4. API (préfixe /api)

Routes publiques
POST login, token/refresh, register, verify-email, verify-email/resend
GET articles?scope=, articles/{slug}, videos, videos/{id}, tournaments?zone=, stats
GET forum/… (catégories, sujets, messages), search?q=, members/{pseudo}
Routes connectées (JWT)
GET/PATCH me, PATCH me/password, GET me/export, DELETE me → email de confirmation → account-deletion/confirm
me/favorites, favoris vidéo, créer sujet / message, abonnements, POST forum/posts/{id}/report
Doc OpenAPI (Nelmio) sur /api/doc en dev uniquement

Conventions : DTO #[MapRequestPayload] + contraintes Validator (messages en français), réponses JSON, pagination commune, rate limiters nommés (register, verification_resend, forum_post, forum_report, search) + login throttling (429).

5. Sécurité et RGPD — à reprendre tels quels

Sécurité

  • Secrets jamais versionnés (.env.local, .env.*.local, *.pem) ; générés sur le serveur par le script d'installation (droits 600).
  • .htaccess : HTTPS forcé, HSTS, CSP stricte (script-src 'self'), X-Frame-Options DENY, fichiers sensibles bloqués.
  • Angular : optimization.styles.inlineCritical: false (sinon un onload inline viole la CSP) ; copier .htaccess via un glob d'assets explicite.
  • CORS limité aux origines du site ; trusted_hosts ; cookies session secure/httponly/samesite.
  • Mots de passe : PasswordStrength niveau moyen ; bêta protégée par Basic Auth + noindex.
  • Vidéos : uniquement CC BY vérifiées, attribution ; lecture au clic via youtube-nocookie (sous-titres FR : cc_load_policy=1&cc_lang_pref=fr).

RGPD

  • Consentement CGU/confidentialité journalisé (version, IP, date).
  • Vérification d'email obligatoire avant de poster.
  • Export JSON des données (me/export).
  • Suppression confirmée par email puis anonymisation (les messages restent, l'auteur devient « Utilisateur supprimé »).
  • Cron app:gdpr:cleanup (comptes non vérifiés, jetons expirés).
  • Pages légales avec champs [À COMPLÉTER] centralisés dans legal.config.ts.
  • Boutique : commandes conservées (obligation comptable) mais détachées du compte anonymisé.

6. Contenus et outils

  • Importeurs idempotents JSON → base : app:articles:import, app:tournaments:import (rejet des URL non http(s), dates invalides).
  • Contenu de base en prod sans compte de démo : app:content:seed (classe partagée App\Content\DefaultContent utilisée aussi par les fixtures).
  • Fixtures (dev) : comptes démo + forum + contenus. app:user:promote email --role=ROLE_ADMIN.
  • Actualités réelles : chaque info vérifiée sur 2 sources, sources citées ; aucun contenu copié de créateurs (droit d'auteur).
  • PDF : HTML imprimé avec Edge headless (--print-to-pdf) depuis un chemin sans espaces ; contrôle avec pdfinfo/pdftoppm (poppler).

9. Méthode de travail (avec Claude Code)

  • Sprints : 0 socle → 1 comptes/RGPD → 2 contenus → 3 forum → 4 profil/légal → 5 finitions/déploiement ; versions SemVer (tag + CHANGELOG à chaque livraison).
  • Agents en parallèle, chacun sur une zone distincte (back / front / contenus) ; fonctionnalités futures sur une branche + worktree séparés et un drapeau désactivé (ex. boutique v2).
  • Consigne aux agents : « expert du domaine » (ex. expert en poker), lecture minimale, rapport court ; vérifier chaque livraison (tests, build, contrôle des sources/licences).
  • Commit + push à chaque étape verte ; aucun secret dans le chat ni dans Git ; jamais de mise en ligne publique sans confirmation.
  • Un CLAUDE.md par projet et des dossiers séparés pour ne pas mélanger deux projets.

10. Check-list pour dupliquer

  1. Choisir thème, nom, domaine ; créer le dépôt GitHub et le dossier local (chemin sans espaces de préférence).
  2. Copier la structure (sections 2–6), renommer les préfixes (backXxx, frontXxx), adapter les enums de portée/zone/niveau au thème.
  3. Rédiger CLAUDE.md, ROADMAP, design (couleurs, police) ; choisir des ports locaux libres.
  4. Produire les contenus vérifiés (JSON d'actualités, calendrier, vidéos sous licence libre, leçons).
  5. Tests verts → tag v0.x → déploiement bêta (section 7) → testeurs → mentions légales → confirmation → v1.0.
